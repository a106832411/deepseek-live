# 鲸live 打包说明（electron-builder）

> 目标：把仓库打成可分发的 Windows 便携版（portable）exe，也支持 NSIS 安装版。
> 本文只讲打包；业务代码不改（`app/main/*.cjs`、`src/**`、`public/**`、`electron/**` 一律没动）。

## 1. 一句话用法

```powershell
npm install            # 首次：会装 electron-builder（已写进 devDependencies）
npm run build:exe      # vite build + 便携版 exe → release\鲸live-<版本>-portable.exe
```

## 2. 环境要求

- Windows 10/11 x64
- Node 22.x（实测 v22.21.1）+ npm 10.x
- 首次打包需要联网，electron-builder 会把工具链下到 `%LOCALAPPDATA%\electron-builder\Cache`：
  - `winCodeSign`（约 5.6 MB，提供 rcedit 写 exe 图标/版本信息）
  - `nsis-3.0.4.1`（约 1.3 MB）+ `nsis-resources-3.4.1`（约 731 KB），portable/安装版都靠它
- GitHub 直连慢的时候用镜像（实测直连 nsis 会超时、镜像 0.6s）：

```powershell
$env:ELECTRON_BUILDER_BINARIES_MIRROR = 'https://npmmirror.com/mirrors/electron-builder-binaries/'
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm run build:exe
```

## 3. 命令一览

| 命令 | 作用 | 产物 |
| --- | --- | --- |
| `npm run build:exe` | 前置检查 + vite build + 便携版（portable） | `release\鲸live-0.1.0-portable.exe` |
| `npm run build:installer` | 前置检查 + vite build + NSIS 安装版 | `release\鲸live-0.1.0-setup.exe` |
| `npm run dist` | 只做 `vite build && electron-builder`，不跑前置检查脚本 | 同 `build:exe` |
| `powershell -File scripts/build-exe.ps1 -SkipBuild` | 复用已有 `dist/`，只重新打包（改完图标/配置时快） | 同上 |
| `... -Target nsis` | 手动指定安装版 | setup.exe |
| `... -NoAsar` | 应急兜底：`asar: false`，产物在 `release-noasar\`（§7.1 已修复，一般不需要） | portable exe |
| `... -NoExeEdit` | 兜底：跳过 rcedit（不往 exe 里写图标/版本信息） | portable exe |

脚本 `scripts/build-exe.ps1` 会依次做：检查 `node_modules`/electron/electron-builder/入口文件 → `vite build` → `electron-builder --win <target> --publish never` → 打印产物绝对路径和大小；失败时给可读报错和常见原因。

## 5. 打包配置：`electron-builder.yml`

- `appId: com.jinglive.deeplive`，`productName: 鲸live`，图标 `assets/icon.png`（1254×1254，electron-builder 自动转 `.ico`）
- `directories.output: release`
- `files` 白名单：`package.json`、`electron/**`、`app/**`、`dist/**`、`public/**`、`assets/**`、`server/**`、`extras/python/**`、`extras/douyin/**`
  - 排除：`node_modules`、`__pycache__`、`*.pyc`、`extras/python/logs`、`*.log`、`logs/`、`config.json`、`config.example.json`、`.env`、`mod-src-patches`、`docs`、`src`、`scripts`
  - 实测 `app.asar` 里没有 `node_modules`（core.cjs 零 npm 依赖、渲染层已被 vite 打进 `dist/`）
- `asarUnpack: extras/python/**, extras/douyin/**` → 解到 `resources\app.asar.unpacked\extras\{python,douyin}\**`
  - python 脚本要从真实路径 spawn；内置抖音中继 `extras/douyin/relay.js` 由 deps.cjs 用 `process.execPath`（打包后是 electron.exe）以 Node 模式跑，脚本路径也必须是真实文件
  - **`public/` 不需要 unpack**：core.cjs 用 `fs.readFileSync(PUBLIC/...)` 读、由 HTTP 服务给浏览器，Electron 的 asar 读补丁对读操作是透明的
- `npmRebuild: false`、`compression: normal`
- `win.target: portable x64`；`artifactName: ${productName}-${version}-portable.${ext}`
- `portable.requestExecutionLevel: user`、`portable.unpackDirName: jinglive-portable`
- `nsis`：`oneClick: false`、`perMachine: false`（装到 `%LOCALAPPDATA%\Programs\鲸live`，无需管理员）、允许改安装目录、建桌面/开始菜单快捷方式

## 6. 用户配置（config.json / .env）怎么放

`config.json`、`.env`、`logs/` **不会打进包**（白名单里也没收），落在运行期的「可写根目录」`DATA_ROOT`：

### 6.1 运行期目录规则（源码 / portable / 安装版）

`app/main/core.cjs` 已按打包场景把路径拆成三段（2026-11-11 适配，见 §7.1）：

| 变量 | 含义 | 打包后取值 |
| --- | --- | --- |
| `ROOT` | 只读资源根 | `...\resources\app.asar` |
| `DATA_ROOT` | 可写根：`logs/`、`config.json`、`.env`、点歌日志、清唱 wav | 优先级：`WT_DATA` 环境变量 → `PORTABLE_EXECUTABLE_DIR`（便携版自动设 = exe 所在目录）→ 打包后 exe 所在目录 → 源码模式 = 仓库根 |
| `EXTRA_ROOT` | `extras/python` 真实路径 | `...\resources\app.asar.unpacked`（源码模式 = 仓库根） |

`electron/main.cjs` 打包时会在 require core 之前设 `WT_DATA = app.getPath('userData')`，
但便携版的 `PORTABLE_EXECUTABLE_DIR` 优先级更高 → **便携版：配置和日志就在 exe 同目录**（`release\logs\`、`release\config.json`）。

所以用户只要把 `config.json` / `.env` 放到 **exe 同目录**即可被读到：

```powershell
# 便携版：release\鲸live-0.1.0-portable.exe 旁边放 config.json / .env
# 想换位置就设环境变量（优先级最高）：
$env:WT_DATA = 'D:\jinglive-data'   # logs/config/.env 都进这个目录
$env:WT_CONFIG = 'D:\jinglive-data\config.json'
$env:DEEPLIVE_ENV = 'D:\jinglive-data\.env'
$env:DEEPLIVE_PORT = 8788
```

- NSIS 安装版（per-user，装到 `%LOCALAPPDATA%\Programs\鲸live`）：没有 `PORTABLE_EXECUTABLE_DIR`，
  默认落到 `app.getPath('userData')` = `%APPDATA%\鲸live`（含 logs/config.json）。
- 源码模式（`npm run electron`）：`DATA_ROOT` = 仓库根，和以前一样读 `config.json` / `.env`。

### 6.2 已实测

便携版（asar 版）实测：`%PORTABLE_EXECUTABLE_DIR%\logs\app.log` 正常生成，
内容为 `未找到配置，使用默认配置` + `鲸live服务已启动: http://127.0.0.1:8798`（见 §8）。

## 7. 已知限制 / 打包注意点

### 7.1 `ROOT` 指向 `app.asar`（**已修复**，2026-11-11 commit 76f9d23）

历史问题：`core.cjs` 里 `ROOT = path.resolve(__dirname, '..', '..')`，打包后 = `...\resources\app.asar`（文件，不是目录），
`fs.mkdirSync(LOG_DIR)`（LOG_DIR = ROOT/logs）抛 `ENOTDIR, not a directory`，主进程 require 阶段即崩，
窗口弹 Electron 错误框、端口不监听。

**现已修复**（Lead 按 §7.1/§7.2 建议改的，不是打包侧改动）：

- `ROOT` = 只读资源（打包后 = `app.asar`，源码 = 仓库根）
- `DATA_ROOT` = 可写根（`WT_DATA` → `PORTABLE_EXECUTABLE_DIR` → 打包后 exe 目录 → 源码 = 仓库根）；
  logs / config.json / .env / 点歌日志 / 清唱 wav 都走它，`mkdirSync` / `saveConfig` 都加了兜底
- `EXTRA_ROOT` = 打包后 `resourcesPath/app.asar.unpacked`（源码 = 仓库根），python spawn 走它
- `electron/main.cjs` 打包时在 require core 前设 `WT_DATA = app.getPath('userData')`，便携版由 `PORTABLE_EXECUTABLE_DIR` 优先接管

**实测（2026-11-11，HEAD 76f9d23 重打）**：便携版 asar 产物正常启动，8798 监听、`/api/health` 200、
`/console` 返回 Vue 构建产物、`/api/deps` 6 个服务、`/api/live2d/models` 有 avatar，日志落在 exe 同目录 `release\logs\app.log`。详见 §8。

### 7.2 `extras/python` 用 unpacked 真实路径 spawn（**已适配**）

`asarUnpack: extras/python/**` → 真实文件在 `resources\app.asar.unpacked\extras\python\`。
`core.cjs` 已改用 `EXTRA_ROOT`（打包后 = `resourcesPath/app.asar.unpacked`）拼 `extras/python/sing_tts.py`，
python.exe 能打开真实路径；源码模式回落仓库根。打包侧不需要再改。

### 7.3 `public/live2d` 不需要 unpack

见 §5：HTTP 静态服务走 `fs.readFileSync`，asar 内读取没问题，已实测 `/` 页面和 live2d 资源能出来（`dist` 里也带了一份 live2d）。

### 7.4 清唱/TTS 的外部依赖不在包里

`extras/python/sing_tts.py` 只是脚本；真正的 Python、GPT-SoVITS 代理（9881）、`D:/sing_gpu` 等模型/环境需要用户自己装好。
打包不包含任何 Python 运行时。

运行环境页对 TTS 的「一键启动」自动发现依赖两处**本机路径**：`scripts/start-all.ps1` 里写的 TTS 工作目录（`$Work`），
以及仓库同级 / 上两级目录的 `whaletalk/gsv_gpu/run_gpu_api.ps1`。

- 本轮已把 `scripts/start-all.ps1` 也打进包里（`files` 白名单，只读文本，Electron 的 fs 能从 asar 读），
  `deps.cjs` 会同时按 `EXTRA_ROOT`（asar.unpacked）和 `ROOT`（asar）两个根去找 —— 所以**只要这个脚本里的 `$Work`
  在本机是对的，打包版 TTS 也能自动发现并一键启动**（实测 `tts.startable=true`）。
- 如果本机没有 `whaletalk/gsv_gpu` 那套脚本，仍然要配 `deps.tts_start_cmd`（写本机实际启动命令），
  否则 `startable` 为 false。OBS / Ollama / Python / 内置抖音中继的自动发现不受影响。

### 7.5 端口

默认 8788。测试/多开时用 `DEEPLIVE_PORT` 换端口（本次实测统一用 8798/8799，避开正在跑的 8788）。
打包本身不监听端口；注意"端口被占自动 +1 顺延"是 core.cjs 的行为，取决于你打的包里的 core 版本。

### 7.6 `ELECTRON_RUN_AS_NODE=1` 会让 Electron 秒退（本机环境特有）

DeepSeek Harness / 某些 IDE 环境下会继承 `ELECTRON_RUN_AS_NODE=1`，此时启动 `electron.exe` 或便携版 exe 会
"一启动就退出"，报 `Cannot read properties of undefined (reading 'whenReady')`。
手动验证产物前先清掉：

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

（只影响"启动测试"，不影响打包本身，打包不启动 Electron。）

### 7.7 winCodeSign 解压失败：`Cannot create symbolic link ... 客户端没有所需的特权`

Windows 默认普通用户不能建符号链接（没开"开发者模式"/不是管理员），而 electron-builder 下载的
`winCodeSign-2.6.0.7z` 里有 darwin 的 `.dylib` 符号链接，`7za` 解压会 `Sub items Errors: 2` 然后整体失败。
现象：`npm run build:exe` 卡在 `packaging` 之后，报 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`。

三种处理，按推荐顺序：

1. **开一次 Windows 开发者模式**（设置 → 系统 → 开发者选项），或右键以管理员身份跑打包脚本。最干净。
2. **手动补缓存**（本次实测用这个，之后打包就正常了，不需要管理员）：
   ```powershell
   $cache = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
   $sevenZip = "C:\Users\49820\Desktop\deepseek-live\node_modules\7zip-bin\win\x64\7za.exe"
   $zip = Get-ChildItem $cache -Filter '*.7z' | Sort-Object LastWriteTime -Descending | Select-Object -First 1
   if (-not $zip) {
     Invoke-WebRequest 'https://npmmirror.com/mirrors/electron-builder-binaries/winCodeSign-2.6.0/winCodeSign-2.6.0.7z' -OutFile "$env:TEMP\winCodeSign.7z"
     $zip = Get-Item "$env:TEMP\winCodeSign.7z"
   }
   New-Item -ItemType Directory "$cache\winCodeSign-2.6.0" -Force | Out-Null
   & $sevenZip x -bd $zip.FullName "-o$cache\winCodeSign-2.6.0" "-x!darwin/*"
   Test-Path "$cache\winCodeSign-2.6.0\rcedit-x64.exe"   # 输出 True 即修好
   ```
   （生成目录名必须是 `winCodeSign-2.6.0`，electron-builder 只认这个名字；只要该目录存在就不再下载/解压。）
3. **兜底跳过 rcedit**：`npm run build:exe -- -NoExeEdit`（等价 `--config.win.signAndEditExecutable=false`）。
   能出 exe，但 exe 图标/公司名/版本信息是 Electron 默认的，功能不受影响。

### 7.8 便携版启动细节

- 首次双击会解压到 `%TEMP%\jinglive-portable`（约 284 MB），启动慢几秒；正常退出会清理。
  强杀进程会留下这个目录（本次测试强杀后手动删了），不影响下次启动（会重新解压）。
- 未被代码签名：Windows SmartScreen 会提示"未知发布者"，要消掉需代码签名证书（本仓库未配置）。
- 便携版 exe 内嵌的 app 是打包时的仓库快照；改完源码要重新打包。

### 7.9 以后加运行时 npm 依赖要注意

现在 `files` 排除了 `node_modules`、且 `npmRebuild: false`，是因为主进程零 npm 依赖、渲染层由 vite 打包。
如果以后主进程 `require` 第三方包，需要把对应的 `node_modules` 纳入打包（去掉排除或改用 dependencies 自动收集），
有原生模块的还要恢复 rebuild。

- 完整日志：`npm run build:exe` 控制台输出；加 `--config.debug=1` 更详细
- 工具链缓存：`%LOCALAPPDATA%\electron-builder\Cache`
