## 2. 做了什么

### 2.1 WSL2 + ROCm 环境（docs/WSL-ROCm搭建.md 有完整步骤）

- Ubuntu 22.04 rootfs 用 `wsl --import` 导入（不依赖商店）
- ROCm 6.4：`amdgpu-install --usecase=rocm --no-dkms`
- torch 2.8.0+rocm6.4 用本地 wheel `--no-deps` 装（避免 pip 因缺 `pytorch-triton-rocm` 去拉 PyPI 的 CUDA torch）
- **能看见 GPU 的关键**：`HSA_ENABLE_DXG_DETECTION=1` + `LD_PRELOAD=/opt/rocm/lib/libhsa-runtime64.so.1`
  （WSL 没有 `/dev/kfd`，torch 自带的 libhsa 不认 `/dev/dxg`）
- 试过 torch 2.7.1+rocm6.3：连 GPU 都看不到（运行时版本不匹配），已还原 2.8.0+rocm6.4

### 2.2 RVC 引擎（鲸live）

`app/main/core.cjs` 新增 `sing.engine="rvc"`：

1. 用现有音源搜原曲 → 下载
2. `extras/python/song-cover/cover.py`（来自唱歌工坊，MIT）跑 demucs 分离
3. RVC 换声（`rvc-python`，声线来自 `voices.json`）
4. 混音 → 转 wav → 接现有放音/歌词时间轴
5. 失败自动回退 TTS 清唱；`dry_run` 只打印命令；`input` 可直接用本地小样测

配置（`config.json → sing.rvc`，默认已是可用值）：

## 3. 实测数据

- demucs：20 秒音频 CPU 15~19 秒；90 秒音频 GPU 25 秒 / CPU 26 秒
- RVC 推理：6 秒音频 4.7~4.9 秒（Windows CPU，torch 2.0 + MKL）
- 完整 cover.py：20 秒音频 ≈ 39~40 秒（分离 17~19s + 换声 20s + 混音 1s）
- 整首 4 分钟估算：**约 6~8 分钟**
- 鲸live `prepareRvc`：20 秒输入 38.7 秒返回 `{outWav, timing:{duration:19.98, engine:'rvc'}}`
- 修了一个 bug：引擎的 `finally` 会把用户用 `sing.rvc.input` 指的小样误删，已改成只删自己下载的原曲

## 4. 拿到声线模型后的步骤

```powershell
# 1) 自检（结构 + 6 秒换声冒烟）
.\scripts\rvc-check-model.ps1 -Model "D:\models\my_voice.pth" -Index "D:\models\my_voice.index" -Sample "D:\music\test.mp3"

# 2) 出一首完整翻唱（约 6~8 分钟）
.\scripts\rvc-cover.ps1 -Model "D:\models\my_voice.pth" -Index "D:\models\my_voice.index" `
  -InputFile "D:\music\宁夏.mp3" -VoiceName 小深 -F0 0

# 3) 让直播点歌走翻唱：config.json 里设
#    "sing": { "engine": "rvc", "rvc": { "voice": "小深", ... } }
```

## 5. 仍然没解决的

1. **WSL GPU 的 RVC segfault**：已确认不是 fp16/cudnn/MIOpen/版本问题能绕过的；要修需要深入 ROCm/DXG 或换 WSL 外的 GPU 方案（如 DirectML 独立环境）
2. **真实音色效果**：要等模型才能听
3. **完整歌曲版权**：只处理用户有权使用的音频；声线模型许可由用户确认
