# 截图识别矿洞洞口/梯子（已实现）

> 实现时间：2026-11-09 21:25
> 代码：`extras/python/vision_ladder.py`
> 模板：`extras/python/assets/hole_tpl.png`、`ladder_tpl.png`

## 一、怎么做的

1. **抓屏**：直接抓 Stardew Valley 窗口画面
2. **模板匹配**：用 OpenCV `matchTemplate`（归一化相关）在画面里找「洞口」和「梯子」两个模板
3. **像素 → 格子**：用 bridge 的 viewport 换算
   ```
   tileX = (px - 8 - 32 + viewport.x) / 64
   tileY = (py - 8 - 32 + viewport.y) / 64
   ```
   （已用玩家实际坐标校验：截图里玩家像素 (670,375) → 换算 (4.92, 28.09)，实际 (5,28) ✅）
4. **接入下楼流程**：`descend_via_ladder()` 里先尝试视觉识别到的洞口/梯子：
   - 走到旁边 → 交互
   - 再尝试踩上去（step_tile）
   - 都失败才回到「快速试附近 → 全图巡逻」

## 二、实测结果

在同一张矿洞截图（3 层）上：

```
截图识别到 3 个候选: [(3, 30, 0.97, 'hole'), (15, 28, 0.85, 'hole'), (15, 29, 0.80, 'hole')]
```

- **真洞口 (3,30) 置信度 0.97**，和人工看图算出的坐标完全一致 ✅
- 模板在原图上匹配分数 **1.0**（自匹配验证）
- 误报可以通过阈值（0.88）过滤掉

## 三、当前的局限与下一步

| 问题 | 说明 | 下一步 |
|---|---|---|
| 模板太少 | 目前只有 1 张洞口 + 1 张梯子模板，不同楼层/季节贴图可能不同 | 跑图时自动保存新的洞口截图，扩充模板库 |
| 洞口触发 | 识别到洞口后，交互/踩上去**还没成功触发下楼**（游戏对“跳洞”有专门的输入判定） | 复刻“按住方向键走向洞口”的输入，或调用 `Farmer` 的下落方法 |
| 视野限制 | 只有洞口在屏幕内才能识别 | 配合巡逻：边走边抓屏 |

## 四、已经确定的收益

- 不用再靠游戏内部字段猜洞口位置
- 只要洞口出现在屏幕上，就能精确拿到格子坐标（误差 0）
- 为「真的没有洞口才离开」提供依据
