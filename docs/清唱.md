# 清唱（AI 用自己的声音清唱）

> 把直播间原来的「点歌 → 播原曲」换成「点歌 → AI 主播用自己的 TTS 声音清唱」：
> 不播放任何受版权保护的原曲，只从网易云抓歌词，逐句用 GPT-SoVITS 合成后做旋律化处理，
> 串成一首无伴奏的「清唱」放出来。旧的「播放原曲」行为保留，改 `songs.perform` 即可切回。

- 入口：弹幕「唱歌 歌名」/「清唱 歌名」/「点歌 歌名」/「/点歌 歌名」
- 页面：`/songs`（清唱列表，OBS 浏览器源）、`/subtitle`（清唱歌词字幕）、`/overlay`（弹幕层）、`/live2d`（皮套按句长张嘴）
- 后端：`app/main/core.cjs`（清唱逻辑全部在这里）
- 音频管线：`extras/python/sing_tts.py`（逐句 TTS → WORLD 旋律后处理 → 串接）

---

## 1. 功能说明

一条弹幕点歌进来后：

1. **识别歌名**：网易云搜一下，拿到标准歌名/歌手（搜不到也不影响，用你输入的名字）。
2. **拿歌词**：抓网易云 LRC 原文，清洗（去时间轴/去作词作曲等制作信息/去纯英文行/长句拆短），
   从后半段（偏副歌）挑 `max_lines` 句、总字数不超过 `max_chars`，相邻重复句去掉。
   抓不到歌名或歌词时：`sing.lyrics=ai` 会先让 AI 现编几句；AI 也不可用时用内置兜底词（见 §7）。
3. **后台合成**：一入队就立刻开始合成（不等轮到它），逐句 TTS → WORLD 改音高 → 串接成一首 wav。
   合成串行排队（避免多首同时压 GPU/TTS），轮到它时通常已经备好。
4. **播报 + 垫话**：开唱前先报幕（`sing.intro`），如果合成还没完成就垫 filler（`sing.filler`，最多垫 2 次），
   然后播放 wav；唱完道谢（`sing.outro`）。
5. **歌词同步**：wav 旁边的 timing json 给出每句的 `start`，后端按 `start` 定时发 `sing line` WS 事件，
   页面（`/songs` 大字歌词、`/subtitle` 字幕、`/live2d` 口型）跟着动；`sing end` 收尾。
6. **队列串行**：多首点歌按顺序一首一首唱，队列清空后 `state.current` 变 `null`。

特点：

- **不播原曲、不下载 mp3**（`perform=sing` 时），没有音乐版权风险；
- 默认 `mode=melody` 会给 TTS 语音「加旋律」（五声音阶/小星星/生日快乐），更像唱歌；
  `mode=read` 是纯念唱（自然朗读节奏，最稳的兜底）；
- 合成失败/没歌词/TTS 挂了都不会开天窗：会退化成「逐句念唱」或 AI 现编歌词。

## 2. 快速启用

`.env`（推荐，密钥/本机路径放这里）：

```ini
# TTS 必须有：GPT-SoVITS 代理（9881 → 9882）
DEEPLIVE_TTS_URL=http://127.0.0.1:9881
DEEPLIVE_TTS_REF_AUDIO=D:/path/to/ref_voice.wav
DEEPLIVE_TTS_PROMPT_TEXT=                # 参考音里说的那句话，必须逐字一致（写错会又平又假，见第 6 节）
DEEPLIVE_TTS_SPEED=0.95

# 清唱参数（可选）：不写就用 config.json / 控制台的默认值；
# 写了会强制覆盖控制台设置（.env.example 里默认注释掉）
# DEEPLIVE_SONGS_PERFORM=sing            # sing=清唱（默认）| play=旧行为播原曲
# DEEPLIVE_SING_ENABLED=true
# DEEPLIVE_SING_MODE=melody              # melody=带旋律 | read=纯念唱
```

`config.json`（或控制台「清唱」页保存）对应：

```json
{
  "songs": { "perform": "sing", "enabled": true, "dedupe": true, "max_queue": 20 },
  "sing": { "enabled": true, "mode": "melody", "lyrics": "netease", "max_lines": 6,
            "max_chars": 100, "intro": true, "outro": true, "melody": "auto",
            "bpm": 92, "vibrato": true, "gap_ms": 320,
            "filler": "我清清嗓子，准备开唱啦～歌词有点长，我再看一眼～马上就好，再等我一下下～" }
}
```

启动服务后弹幕发「唱歌 稻香」即可。控制台（Electron 或 `/console`）的「清唱队列」页可看当前/排队，
「配置 → 🎤 清唱」页可改全部参数（保存经 `POST /api/config` 即时生效）。

> 配置优先级：**真实环境变量 > `.env` > `config.json` > 内置默认值**。
> 也就是说 `.env` 里写了某个 `DEEPLIVE_SING_*`，`config.json`/控制台里改它不会生效（控制台保存后会被 .env 覆盖回来）。
> 所以 `.env.example` 里这些 `DEEPLIVE_SING_*` 默认是**注释掉**的：不写就用 `config.json`/控制台的值（推荐）；
> 只有想用 `.env` 强制钉死某个参数时才取消注释。

## 3. 弹幕命令

| 弹幕 | 行为 |
|---|---|
| `点歌` / `點歌` / `清唱` | 没带歌名 → 从 `sing.pick_list` 随机挑一首 |
| `点歌 稻香`、`点歌稻香`、`点歌：稻香`、`清唱 晴天`、`/点歌 宁夏`、`／点歌 宁夏` | 点指定歌名（兼容全角斜杠/冒号） |
| `唱歌` / `唱一首` / `唱一个` / `来一首` / `来首` / `唱`（单独出现） | 随机挑一首 |
| `唱歌 稻香`、`唱歌：稻香`、`来首 宁夏`、`唱 晴天` | 点指定歌名；**唱歌/唱这首类命令必须用空格或冒号分隔歌名** |
| `《稻香》`、`「稻香」` 形式的引号会被去掉 | — |
| `跳过` / `切歌` / `别唱了` / `不唱了` / `stop` / `skip` | 跳过当前清唱，并回一句「好，那这首就唱到这儿～」（弹幕路径仅在有当前清唱或队列非空时生效，见 §5.3） |

命中规则（`core.cjs` 里按优先级 5 条正则）：

```js
// 1) 点歌/點歌/清唱：后面有没有空格都行，没歌名就随机
/^[/／]?\s*(?:点歌|點歌|清唱)\s*[:：]?\s*(.*?)\s*$/
// 2) 唱歌/唱一首/唱一个/来一首/来首/唱：必须用冒号分隔（避免「唱歌比赛开始了吗」误命中）
/^[/／]?\s*(?:唱歌|唱一首|唱一个|来一首|来首|唱)\s*[:：]\s*(.*?)\s*$/
// 3) 同上但用空格分隔
/^[/／]?\s*(?:唱歌|唱一首|唱一个|来一首|来首)\s+(.+?)\s*$/
// 4) 单独「唱 歌名」
/^[/／]?\s*唱\s+(.+?)\s*$/
// 5) 只有命令词、没有歌名 → 随机
/^[/／]?\s*(?:点歌|點歌|清唱|唱歌|唱一首|唱一个|来一首|来首|唱)\s*$/
```

注意：

- **必须以下面的命令词开头**才算点歌；「唱得真好听」「我想唱歌」「唱歌真好听」不会入队，会走正常聊天/AI 回复。
- 「唱歌」类命令改成「空格/冒号分隔」后，「唱歌比赛开始了吗」不再误命中；但「唱歌 比赛开始了吗」仍会把「比赛开始了吗」当歌名。
  介意的话把这类词加进 `filter.blocklist`。
- 命令处理在固定回复/AI 回复之前；`events.danmaku.cooldown_user`（默认 5 秒）对同一用户先生效——
  同一人 5 秒内连发多条弹幕只有第一条会被处理（包括点歌）。
- 命中命令但失败时（仅弹幕路径）会补一句语音提示：去重 →「xx，这首本场唱过啦，换一首吧～」；
  关闭 →「清唱暂时关掉啦，等会儿再唱～」；空歌名 →「想听哪首呀？说个歌名给我～」。
  队列满/没歌词的提示在 `requestSing()` 里发；直接调 API 时只返回 JSON error。
- 点歌接口在「抓完歌词、入队」就返回，语音回执（「点好啦，排第几个」）是排队播放的，不阻塞接口。

## 4. 配置项

### 4.1 `songs.*`（点歌总开关 / 兼容旧播放）

| config 键 | .env | 默认 | 说明 |
|---|---|---|---|
| `songs.perform` | `DEEPLIVE_SONGS_PERFORM` | `sing` | `sing`=清唱；`play`=旧行为（下载并播放原曲） |
| `songs.enabled` | `DEEPLIVE_SONGS_ENABLED` | `true` | 点歌/清唱总开关；关掉后 `/api/songs/request` 返回「清唱已关闭」 |
| `songs.internal` | `DEEPLIVE_SONGS_INTERNAL` | `true` | 使用内嵌网易云搜索（`play` 模式外挂点歌文件时用） |
| `songs.dedupe` | `DEEPLIVE_SONGS_DEDUPE` | `true` | 本场同歌去重（按歌名归一化：大小写/空格/标点不敏感） |
| `songs.max_queue` | `DEEPLIVE_SONGS_MAX_QUEUE` | `20` | 队列入队上限（队列满回语音提示） |
| `songs.sources` | `DEEPLIVE_SONGS_SOURCES` | `netease,qq` | 音源优先级（仅 `play` 模式播原曲用） |
| `songs.auto_play` | `DEEPLIVE_SONGS_AUTO_PLAY` | `true` | 旧字段/兼容 |
| `songs.request_file` | — | `song_requests.jsonl` | `play` + `internal=false` 时点歌转交文件 |

### 4.2 `sing.*`（清唱）

| config 键 | .env | 默认 | 说明 |
|---|---|---|---|
| `sing.enabled` | `DEEPLIVE_SING_ENABLED` | `true` | 启用清唱；和 `songs.enabled` 是「与」关系 |
| `sing.mode` | `DEEPLIVE_SING_MODE` | `melody` | `melody`=带旋律清唱（WORLD 改音高，默认走「自然旋律」预设）；`read`=纯念唱（只做响度/淡入淡出，最稳） |
| `sing.lyrics` | `DEEPLIVE_SING_LYRICS` | `netease` | `netease`=抓原歌词；`ai`=跳过抓词直接让 AI 现编（避免版权歌词） |
| `sing.max_lines` | `DEEPLIVE_SING_MAX_LINES` | `6` | 每首唱几句（1~12，代码会 clamp） |
| `sing.max_chars` | `DEEPLIVE_SING_MAX_CHARS` | `100` | 整首歌词总字数上限（≥20） |
| `sing.intro` | `DEEPLIVE_SING_INTRO` | `true` | 开唱前报幕「一首《x》，清唱版，献丑啦～」 |
| `sing.outro` | `DEEPLIVE_SING_OUTRO` | `true` | 唱完道谢「唱完啦，谢谢 xx 点的歌～」 |
| `sing.melody` | `DEEPLIVE_SING_MELODY` | `auto` | `auto`/`xiaoxingxing`/`shengri`/`folk1`/`folk2`（`auto` 按随机 seed 选；folk2 用不同的模板偏移，听感与 folk1 不同） |
| `sing.bpm` | `DEEPLIVE_SING_BPM` | `92` | 节拍，用于句中音头轻量化吸附（±80ms 内） |
| `sing.vibrato` | `DEEPLIVE_SING_VIBRATO` | `true` | 颤音开关（关掉=0；「自然旋律」预设下为 0.3≈±6 音分） |
| `sing.natural` | —（config.json/控制台高级 JSON） | `true` | melody 是否走「自然旋律」预设（音符锚定融合 0.55、弱颤音 0.3、不硬量化、句尾轻拖 1.25）；关掉回到旧版硬旋律（更机械，一般别关） |
| `sing.v2` | `DEEPLIVE_SING_V2` | `true` | 「唱腔化 v2」：按节拍拉长每字元音、字间连唱、长音颤音渐弱（比"旋律朗读"更像唱；整首会变长 1.5~2 倍） |
| `sing.beat_scale` | `DEEPLIVE_SING_BEAT_SCALE` | `0.75` | v2 档位：`0.55` 保守 / `0.75` 中等（推荐）/ `0.95` 明显（拖更长） |
| `sing.gap_ms` | `DEEPLIVE_SING_GAP_MS` | `380` | 句与句之间的静音间隔（毫秒） |
| `sing.engine` | `DEEPLIVE_SING_ENGINE` | `tts` | `tts`=TTS 清唱（快，默认）；`ace`=**真唱**（本地 ACE-Step 生成纯人声 + Seed-VC 换声，慢但真唱） |
| `sing.ace.*` | —（config.json/控制台高级 JSON） | 见 §6.5 | 真唱引擎路径与参数（python/脚本/duration/cfg/steps/tags） |
| `sing.filler` | `DEEPLIVE_SING_FILLER` | 见下 | 合成没完成时的垫话；合成慢会**循环垫最多 2 次**；设 `false`/空可关 |
| `sing.pick_list` | —（只能用 config.json/控制台） | 10 首儿歌/流行 | 「唱歌」不带歌名时随机挑的候选 |

当前内置默认 `filler` 和本机 `.env` 都是长版（实测整段语音约 **8.6 秒**）：

```
我清清嗓子，准备开唱啦～歌词有点长，我再看一眼～马上就好，再等我一下下～
```

配合开唱报幕（约 4.9 秒），一次报幕 + 一次长垫话约 13.5 秒；合成慢时再垫第二次，最长可覆盖约 22 秒。
`filler` 的值最终以 **`.env` 优先**（`.env` 里写了就覆盖 `config.json`/控制台的值）。

## 5. API

### 5.1 `GET /api/songs/state`

`perform=sing`（默认）时：

```json
{
  "mode": "sing",
  "sing": { "enabled": true, "style": "melody", "lyrics": "netease" },
  "playing": true,
  "current": {
    "name": "稻香", "artist": "周杰伦", "by": "观众A", "source": "netease",
    "lyrics": ["换个梦不就得了", "为自己的人生鲜艳上色", "…（共 6 句）"],
    "lyricIndex": 2,
    "audio": "logs/sing/20261107162155_稻香.wav",
    "duration": 18.41,
    "t": 1794068622455
  },
  "queue": [{ "name": "晴天", "by": "观众B" }]
}
```

- `sing.enabled`：`sing.enabled && songs.enabled` 的实际结果
- `sing.style`：即 `sing.mode`；`sing.lyrics`：歌词来源
- `current`：没有在唱时是 `null`；`lyrics`/`lyricIndex`/`audio`/`duration` 都是清唱字段
- `audio` 是相对项目根目录的路径（`logs/sing/*.wav`），唱完/跳过后 `current=null`

`perform=play`（旧行为）时返回旧形状：

```json
{ "mode": "play", "current": { "name": "晴天 (原唱 …)", "artist": "RyaVocal", "by": "观众A", "source": "netease" },
  "playing": true, "sources": ["netease", "qq"], "queue": [{ "name": "…", "by": "观众A" }] }
```

（`songs.internal=false` 时旧代码会去 `127.0.0.1:9886` 取外挂点歌系统的状态，本仓库默认不用。）

### 5.2 `POST /api/songs/request`

```json
{ "name": "观众A", "query": "稻香" }
```

- `name`：点歌人（用于报幕/道谢）；`query`：歌名（空/不传 → `pick_list` 随机）
- 成功 `200`：`{ "ok": true, "position": 1, "song": { "name": "稻香", "artist": "周杰伦" } }`
  （抓歌词 + 入队后立即返回，语音回执排队播出，不阻塞接口）
- 失败 `400`：`{ "ok": false, "error": "本场已唱过" | "队列已满" | "清唱已关闭" | "空歌名" | "没拿到歌词" }`
- `perform=play` 时同一接口走旧的 `requestSong`（会去搜音源/下载原曲）

### 5.3 `POST /api/songs/skip`

无 body。返回 `{ "ok": true }`（排队场景会带 `"skipped": "歌名"`）。语义（新版）：

1. **正在清唱**（`state.song.current` 存在）→ 打断播放/合成等待，尽快发 `sing end`，队列继续下一首；
2. **还在排队**（current 空、queue 有歌）→ 直接把队首那首去掉（日志「跳过排队中的清唱」），该首不会开唱；
3. **什么都没在唱但有点歌请求正在查歌词**（`state.song.inflight > 0`）→ 打一个 3 秒有效标记，
   这 3 秒内开始的清唱会被取消（日志「清唱跳过（3 秒内新开始的清唱会取消）」）；
4. **完全空闲** → 只返回 ok，不影响之后点歌（日志「清唱跳过：当前没有在唱的歌」）。

注意：

- 弹幕「跳过」只在「有 current 或队列非空」时才调用 skip（`core.cjs:1148`），所以场景 3 只能通过
  `/api/songs/skip`（控制台按钮/脚本）触发。
- 场景 2/3 被跳过的那首会从队列移除，不会留下残留项（已回归验证）。

### 5.4 WS `/ws` 事件（清唱相关）

| 事件 | 字段 | 时机 |
|---|---|---|
| `{kind:'sing',action:'start'}` | `title, artist, by, lyrics[]` | 开始报幕（合成可能还在跑） |
| `{kind:'sing',action:'line'}` | `idx, text, dur`（该句秒数） | 按 timing 的 `start` 逐句推送，页面用它出歌词/张嘴 |
| `{kind:'sing',action:'end'}` | — | 唱完 / 跳过 / 兜底念唱结束 |
| `{kind:'song',action:'queued'}` | `queue`（排队数） | 点歌入队（`play` 模式同样有） |
| `{kind:'speak'}` / `{kind:'speak_end'}` | `text` | 报幕、垫话、道谢、普通说话都走同一 TTS 队列 |
| `{kind:'hello'}` | `session, config, stats, recent` | 连接建立时（页面首屏兜底用） |

示例（真实抓取）：

```json
{"kind":"sing","action":"start","title":"童年","artist":"罗大佑","by":"观众A","lyrics":["心里初恋的童年","总是要等到睡觉前","…"],"t":1794068622455}
{"kind":"sing","action":"line","idx":0,"text":"心里初恋的童年","dur":2.465,"t":1794068638455}
{"kind":"sing","action":"end","t":1794068656284}
```

### 5.5 测试用接口（排障/自动化）

```bash
# 起会话（handleEvent 需要 state.started=true）

# 注入一条弹幕（等价于抖音中继投递）

  -H "Content-Type: application/json" \
  -d '{"event":{"type":"danmaku","name":"测试","text":"唱歌 稻香"}}'

# 直接点歌（不走弹幕）
curl -X POST http://127.0.0.1:8788/api/songs/request -d '{"name":"测试","query":"晴天"}'
```

`scripts/test-sing.cjs` 是端到端冒烟脚本（打完一首完整清唱）：

```bash
node scripts/test-sing.cjs                          # 默认 8788
node scripts/test-sing.cjs --url http://127.0.0.1:8798 --song 稻香 --timeout 180
```

## 6. 音频实现原理

> ⚠️ **声音「机械、没情绪、太假」先查这两件事（本机实测）：**
>
> 1. `tts.prompt_text` 必须和参考音**逐字一致**。写错/写占位符时，同一句 25 字只出 1.0~1.9 秒、语调几乎为零
>    （f0 标准差 1.1~1.5 半音）；改对后是 5.2~7.3 秒、2.7~4.4 半音，明显像人说话。
>    本机参考音 `ref_小奶音_7s.wav` 的正确文本是「梁山在上，今天大白饭也要变得美味呀。」。
> 2. TTS 参数：`temperature` 1.15~1.3 / `top_k` 25~30 / `repetition_penalty` 1.1~1.2
>    比默认 1.0/20/1.35 自然得多；`repetition_penalty` 太高会念成「一个字一个字」。
>
> 这两项对普通聊天回复同样生效（同一套 TTS），改完主播整体说话都会自然一点。

### 6.1 后端调用契约（`core.cjs` → `sing_tts.py`）

`doPrep()` 把歌词写进 `<out>.lines.json`，用当前 python 起一次 `sing_tts.py`：

```
sing_tts.py
  --lines-file  <out>.lines.json     # JSON 数组：["句1","句2",...]
  --out         logs/sing/<时间戳>_<歌名>.wav
  --timing-out  <out>.timing.json
  --tts-url     tts.api_url          # 默认 http://127.0.0.1:9881
  --ref-audio   tts.ref_audio        # GPT-SoVITS 参考音
  --prompt-text tts.prompt_text     # 必须和参考音逐字一致
  --speed       0.95
  --top-k       25                  # 约等于 tts.top_k
  --temperature 1.15                # 约等于 tts.temperature
  --repetition-penalty 1.15         # 约等于 tts.repetition_penalty
  --sample-steps 32
  --mode        melody|read
  --melody      auto|xiaoxingxing|shengri|folk1
  --bpm         92
  --vibrato     1|0
  --gap-ms      320
  --seed        随机
```

产物：

- **wav**：单声道 32000 Hz PCM16。结构 = 0.30s 开头留白 + 每句音频（句间 `gap_ms`）+ 0.40s 结尾留白。
- **timing.json**：

```json
{
  "ok": true, "sr": 32000, "duration": 18.41, "tts_gen": 5.76,
  "fallback": null, "mode": "melody", "melody": "folk1", "bpm": 92, "gap_ms": 320,
  "seed": 1234, "elapsed": 10.6,
  "lines": [
    { "i": 0, "text": "换个梦不就得了", "start": 0.3, "dur": 3.7 },
    { "i": 1, "text": "为自己的人生鲜艳上色", "start": 4.32, "dur": 3.9 }
  ]
}
```

后端只用 `duration` 和每行 `start`/`dur`：`setTimeout(start*1000)` 到点发 `sing line`，
同时 `playWavHandle(outWav)` 播放，播完发 `sing end`。
`--debug` 时每行还会多一个 `notes` 字段（`midi` 音高数组、`syllables` 音节数、`bounds` 音节边界）；
**后端正常路径不传 `--debug`**，所以生产产出的 timing 里没有 `notes`。

歌词在进管线前会先过滤（`core.cjs` 的 `cleanLyricLine`）：去掉 LRC 时间标签/行号、去掉作词/作曲/编曲等制作信息行、
**去掉不含中文的行和少于 3 字的行**（例如「……」这类纯标点行本来就会被丢掉）、超长句按标点拆短取第一段。
所以管线拿到的每一句都是有意义的中文短句；个别句子 TTS 仍可能报错，由 §6.4 的重试 + 静音占位策略兜住。

### 6.2 `mode=melody`（默认，带旋律）

> **2026-11 改版 A（自然旋律）**：`melody` 默认走「自然旋律」(`--natural`，等价于 `--blend 0.55 --blend-mode note
> --vibrato 0.3 --quantize-ms 0 --tail-stretch 1.25 --tail-fall 0.35`)：音级严格跟旋律走，
> 但只把原句**音符内**的自然起伏按 45% 混进来，去掉硬量化和强颤音，句尾轻拖长/下滑。
> 实测比旧版机械感下降（相邻帧音高变化<15 音分的比例 0.67→0.58），旋律保留度仍 0.92。
> 想复现旧版硬旋律：`sing.natural=false` 或直接给 `sing_tts.py` 传 `--blend 1 --vibrato 1`。

> **2026-11 改版 B（唱腔化 v2，默认开启）**：光有旋律还是像"用调子朗读"，v2 解决**时值**：
> 按 bpm 给每个音节分配目标时值（句尾更长），只把 **voiced 元音帧**做 WORLD 帧级拉伸（辅音 ≤90ms、
> 字间停顿 ≤40ms 连唱），长音加 5.5Hz 颤音 + 渐弱、句尾下滑。实测每字时长 0.30s → 0.56s（中等档，
> 句尾 1.01s）、句内最长静音 0.36s → 0.16s，无吞字、无爆音、音高仍锁旋律（逐字误差 11~14 音分）。
> 代价：整首变长（4 句约 17.6s vs 10.1s）。三档由 `sing.beat_scale` 控制；不想要就 `sing.v2=false`。

1. 逐句请求 `/tts` 合成，解码 → 重采样到 32k → 剪掉句首句尾静音（保留 40ms 起音/100ms 尾音）。
2. 用 pyworld（WORLD）分解每句：`harvest` 提 f0、`cheaptrick` 提频谱包络、`d4c` 提非周期成分。
3. 只替换 **voiced 帧**的 f0 为旋律音高（清辅音/气声的 unvoiced 帧保持 0，所以咬字还在）：
   - 音节边界：先按 voiced 帧数均分，再往 ±80ms 内能量谷底吸附；再做 ±`bpm` 节拍网格轻量化；
   - 滑音：音程间 40ms Hann 平滑；颤音：5.5Hz ±20 音分（音头/音尾淡入淡出，短音符按自身时长的 25~30% 收窄）；
   - 微漂移 ±5 音分、每音符随机音准 ±4 音分、保留 18% 原句音高起伏（封顶 ±0.4 半音）压机器人味；
   - 全曲统一移调：按各句中位音高加权中位数定主音，目标音高限制在句中位音高 **±5 半音**内。
4. 每句响度归一到 -18 dBFS（只统计有声帧），峰值 ≤ -1 dBFS，6ms 淡入/15ms 淡出。
5. 旋律来源：`auto` 按 seed 选 —— `folk1`（原创五声音阶走向，3 套模板 + 旋转，最常用）、
   公版《小星星》、公版《生日快乐》；音高按主播音域自动定调，所以不会「高不上去」。
6. 串接成一首；任意一句 WORLD 处理失败 → 该句回退 read 处理（timing 里 `fallback:"read"`）；
   整条 melody 管线异常 → 整首回退 read。

### 6.3 `mode=read`（纯念唱）

逐句 TTS 原样串接，只做响度归一（-20 dBFS）和淡入淡出，不改音高。合成快（少了 WORLD），最稳，适合：
- GPU 弱/分不出 pyworld 资源的机器；
- 想更快出歌、少点「机器味」但接受「念」的效果；
- melody 出问题时临时切过来。

### 6.4 可靠性

- 单句 TTS 失败重试 1 次；仍失败 → 该句用 1.0s 静音占位，timing 里 `failed:true`，整首继续（不全废）。
- 全部句子都失败 → `exit 2` + `timing.ok=false` → 后端判「清唱合成失败」，轮到它时走逐句念唱兜底。
- 合成子进程超时 300s（`runPy`），超时 kill 后同样走兜底。
- 每首合成/播放完成后 `pruneSingFiles()` 只保留 `logs/sing/` 下每种后缀最新 20 个文件。

### 6.5 真唱引擎（可选，`sing.engine=ace`）

TTS 终究是"念稿"，想真唱可以切到本地方案（2026-11 新增，前置部署见下）：

```
点歌歌词 → ACE-Step（音乐生成模型，Apache-2.0）生成 20s 纯人声 a cappella
        → Seed-VC（零样本歌声转换）把音色换成主播参考音（小奶音）
        → 播放（无伴奏）＋按句发歌词事件
```

- 前端调用契约（可替换脚本）：
  - `ace.python` + `ace.script`：`ace_sing.py --lyrics-file X --tags "..." --duration 22 --seed N --out Y --json-out J`
  - `ace.svc_python` + `ace.svc_script`：`convert.py --source Y --ref 小奶音.wav --out Z --cfg 0.75 --steps 30 --json-out J`
  - 默认路径：`D:/sing_gpu/venv/Scripts/python.exe` + `D:/sing_gpu/ace_sing.py`、`D:/seedvc/venv/Scripts/python.exe` + `D:/seedvc/convert.py`
- 每次随机 `ace.tags` 中一组 + 随机 seed → **旋律/唱法不固定**；歌词自动截到 4 句/64 字以内（22s 内唱得完）。
- 失败（脚本缺失/进程崩/OOM/生成失败）→ 自动回落到 TTS 清唱（v2），不会开天窗。
- 实测（RX 7900 GRE 16GB / ROCm，2026-11-08 端到端验证，产出 11.98s、峰值 -1dBFS、有声帧 64%、f0 中位 287Hz）：
  - ACE-Step：12s 音频 / 8 步 = **96.9s**（含约 30s 模型加载），显存峰值 ~8.5GB；热机同参数约 67s。
  - Seed-VC：12s 音频 / 20 步 = **123.6s**，显存 ~3.6GB（ROCm 上 RTF 偏慢）。
  - **点歌 → 出音频约 3.7 分钟**；播放 12s 后结束。默认 `sing.ace.duration=12 / infer_steps=8 / steps=20` 就是按这个速度定的。
  - 失败重试：ACE/Seed-VC 各失败会自动重试 1 次（主机内存/显存偶发紧张时），仍失败才回退 TTS。
  - 提速建议：ACE `--serve` 常驻可省每次 ~30s 模型加载；Seed-VC `steps 15`、源唱 10s 可再快；不要和 ComfyUI/大模型并发（显存/主机 commit 不够会 MemoryError）。
- 已知限制：ACE 咬字/旋律质量随机（需要多试 seed/tags）；Seed-VC 换声后音色接近但吐字/旋律保真会略降（实测 f0 残差相关 0.83~0.95、音域整体平移是预期）；两者都吃显存，和 TTS 引擎同时跑要留够余量。

## 7. 调参建议

| 想调整 | 改什么 | 建议 |
|---|---|---|
| 更像唱歌 / 更稳 | `sing.mode` | 先 `melody`；如果经常破音/吞字或机器吃不住 pyworld，换 `read` |
| 换旋律套路 | `sing.melody` | `auto`（推荐，随机不腻）；指定 `xiaoxingxing`/`shengri`/`folk1`/`folk2`（folk2 与 folk1 模板走向不同） |
| 节奏更准/更慢 | `sing.bpm` | 80~100 之间试；只影响音节吸附，不是真伴奏速度 |
| 句间停顿 | `sing.gap_ms` | 250~500；太小像赶集，太大像断气 |
| 每首长度 | `sing.max_lines` / `sing.max_chars` | 6 句/100 字约 15~25s；想短点 4 句/60 字 |
| 合成等待期的空档 | `sing.filler` | 默认长垫话（约 8.6s、最多垫 2 次，见 §4.2）；设 `false` 可关 |
| 颤音强弱 | `sing.vibrato` | 默认开；觉得「抖」就关掉 |
| 语速/音色 | `tts.speed` / `tts.ref_audio` | 0.9~1.05；换参考音会整体变声（清唱/说话都会变） |
| 声音机械/没情绪 | `tts.prompt_text` / `tts.temperature` / `tts.top_k` / `tts.repetition_penalty` / `sing.mode` | **先查 prompt_text 是否和参考音逐字一致**；本机推荐 1.3 / 30 / 1.1（默认值）；还嫌机械就把 `sing.mode` 换 `read` |
| 清唱有电子味 | `sing.mode` | 换 `read`（纯念唱）；或试 `sing.natural=false` 对比旧版硬旋律 |
| 像念稿、没有唱法 | `sing.v2` / `sing.beat_scale` | 默认已开 v2 中等档；想更拖就调到 0.95，觉得太拖/太闷降到 0.55；关掉 v2 会回到"旋律朗读"（旧版） |
| 想真唱（不是 TTS） | `sing.engine` | 切 `ace`（本地部署 ACE-Step + Seed-VC，见 §6.5）；慢、要 GPU，失败自动回落 TTS |
| 旋律太固定 | `sing.ace.tags` / `sing.melody` | ace 每次随机 tags+seed → 新旋律；tts 的旋律是固定预设（小星星/生日快乐/五声音阶），想换风格只能换预设 |
| 彻底要"有情绪" | `tts.ref_audio` + `tts.prompt_text` | 换/录一条 5~10s 本身带笑带起伏的干净人声做参考音（音色会变一点，但这是唯一根治路线，见 §12.11） |
| 点歌随机池 | `sing.pick_list` | 换成你直播间的常点曲目 |
| 队列太长 | `songs.max_queue` | 默认 20；直播间人多可降到 5~8 |

实测性能参考（本机 32G/GPU，真 TTS）：

| 项目 | 数值 |
|---|---|
| 单句 TTS（短句） | 约 0.5~1.5s 合成 |
| 6 句 melody 一首合成 | 约 15~24s（含并发时 TTS 排队） |

| 点歌→整首唱完 | 约 35~50s |

## 9. 排障

### 9.1 TTS 不通 / 清唱没声音

按顺序查：

1. 代理在不在：`curl http://127.0.0.1:9881/health`（代理 9881 → GPT-SoVITS 9882，两个端口都要通）。
2. 直接打一句 TTS：

   ```bash
   curl -X POST http://127.0.0.1:9881/tts -H "Content-Type: application/json" \
     -d '{"text":"测试","text_lang":"zh","ref_audio_path":"D:/path/ref.wav","prompt_text":"","prompt_lang":"zh","text_split_method":"cut0","batch_size":1,"speed_factor":0.95,"sample_steps":32}'
   ```

   返回 200 且 >1KB 的 wav 才算正常（实测短句约 0.8s、60KB+）。
3. 参考音：`.env` 的 `DEEPLIVE_TTS_REF_AUDIO` 必须是**存在的绝对路径**；路径错时 `sing_tts.py` 直接
   `失败：参考音不存在`、`exit 2`（日志 `logs/app.log`）。
4. 日志关键字（`logs/app.log`，也打印在服务 stdout）。新版日志每行带端口前缀（如 `[p8798]`），
   多开测试服务时能分清是哪个进程：

   | 日志 | 含义 |
   |---|---|
   | `清唱合成开始: 《x》 melody / auto` | 入队后立刻开始合成 |
   | `清唱合成结束 code=0 用时 16.5s` | 合成成功 + 耗时 |
   | `清唱 python stderr: …` | 失败原因（TTS/参考音/pyworld） |
   | `清唱合成失败（将在轮到它时逐句念唱兜底）` | 进兜底 |
   | `《x》走逐句念唱兜底` | 逐句 ttsSpeak，每句一条 `sing line`，最后 `sing end` |
   | `清唱已取消（排队时跳过）: 《x》` | 排队/查歌词期间按了跳过，这首不开唱 |
   | `跳过排队中的清唱: 《x》` | skip 直接把队首去掉了 |
   | `TTS 异常: …` / `TTS 失败 http=…` | 普通说话/报幕的 TTS 也挂了 |

### 9.2 合成失败/很慢

- 6 句 melody 正常 15~24s；明显更慢通常是 GPT-SoVITS 被别的请求占着（合成期间报幕/垫话也走同一个 TTS），
  或 Python 环境缺 `pyworld`/`soundfile`/`numpy`。
- 确认 Python：`D:\gsv_rocm_gpu\venv\Scripts\python.exe`（`pythonPath()` 优先用它，否则 `python`）。
  自检：`python -c "import numpy, pyworld, soundfile"`。
  本机 venv 已装 `pyworld 0.3.5`；换机器/重建 venv 后补装一次：
  `D:\gsv_rocm_gpu\venv\Scripts\python.exe -m pip install pyworld --index-url https://repo.huaweicloud.com/repository/pypi/simple`
- 缺 pyworld 时 melody 会整首回退 read（timing `fallback:"read"`），不会开天窗。
- TTS 完全不通：每句重试后判失败（约 10~30s），再逐句念唱兜底（每句也会尝试 TTS，所以还是没声但事件正常、
  队列不卡）。修好 TTS 后新点一首即可，不用重启。

### 9.3 没歌词 / 歌词不对

- 网易云接口偶尔抽风/限流：`取歌词失败`/`网易云搜索失败` → 自动回退 AI 编词（`sing.lyrics=ai` 时直接编）。
- AI key 没配或调用失败 → 用内置兜底 4 句（`今天想唱一首《歌名》/没有伴奏也没关系/清唱一段送给你/希望你喜欢呀`）。
- 想完全避开版权歌词：`sing.lyrics=ai` + `DEEPLIVE_AI_KEY` 配好，就是 AI 现编原创小段。
- 歌名太冷门搜不到：用歌名原文当标题，能抓歌词就唱；抓不到就 AI 编词。
- **纯标点/无中文/少于 3 字的歌词行会在进管线前就被过滤掉**（例如「……」「Oh~」这类），
  不会送去 TTS，也不会因为这种行报错；个别句子 TTS 真的失败时，`sing_tts.py` 会重试 1 次，
  仍失败就用 1.0s 静音占位并在 timing 里标 `failed:true`，整首继续。

### 9.4 点了没反应 / 队列不动

- 会话没开始：`handleEvent` 要求 `state.started=true`（控制台点「开始」或 `POST /api/session/start`）。
- 同一用户 5 秒冷却（`events.danmaku.cooldown_user`）。
- 弹幕被过滤词命中（`filter.blocklist`，默认「送出」「送出了」）。
- 关了 `songs.enabled`/`sing.enabled`：弹幕命令会回一句「清唱暂时关掉啦」；直接调 API 只有 JSON error。
- 队列满（`songs.max_queue`，会回一句语音提示）。
- 重复点歌（本场已唱过：弹幕会回「这首本场唱过啦」；API 只有 JSON error）。

### 9.5 想回到「播原曲」

`DEEPLIVE_SONGS_PERFORM=play`（或控制台「表演模式 → 播放原曲」）。`/api/songs/state` 会变回旧形状，
弹幕命令走旧的 `requestSong`（搜音源→下载 mp3→播放），清唱参数全部不生效。

### 9.6 无音频设备/服务器上测试

设 `WT_NO_AUDIO=1`：`playWavHandle` 不真的出声，但清唱会按 timing 把时间轴实时走一遍（歌词事件照发），
适合 CI/远程验证。注意它**不会**让 `POST /api/songs/skip` 在「播放中」立即生效（假播放不响应 kill），
真实音频模式才是 `kill()` 立即停。

`WT_CONFIG=<json 路径>` 可指定另一份配置文件（测试用，避免污染 `config.json`；用 UTF-8 无 BOM 保存）。

## 12. 已知问题 / 限制（截至 2026-11-08 验证）

1. **跳过不是「瞬间静音」**：正在清唱（current 存在）时点跳过，真音频模式会 `kill()` 播放进程、很快收到 `sing end`；
   但如果处在「合成等待期」（报幕/垫话已说完、合成还没完），要等 `await prepP` 返回后才发 end（实测约 7s，取决于剩余合成时间），
   好处是**不会再开唱**。`WT_NO_AUDIO=1` 测试模式下「播放中」跳过也不立即 end（假播放不响应 kill，会等时间轴走完）。
2. **首句前的空档**：单首冷启动合成约 15~24s；报幕（约 4.9s）+ 长垫话（约 8.6s，最多垫 2 次）通常能盖住，
   但 TTS 被合成请求占满时垫话自身也有合成等待，极端情况下仍可能出现数秒空白。介意可把 `filler` 再写长些。
3. **`songs.max_queue` 并发竞态**：上限检查在搜索/抓词之前（`doRequestSing()` 里先查队列、再 await 网络、最后 push），
   两个请求同时进来可能都通过检查，队列最多超 1 首。弹幕中继是顺序处理的，实际影响很小。
4. **命令误伤**：以「唱歌」开头但其实是闲聊、且用了空格/冒号的弹幕（如「唱歌 比赛开始了吗」）仍会被当点歌；
   不带分隔符的「唱歌比赛开始了吗」已不会命中（见 §3）。介意的话把这类词加进 `filter.blocklist`。
5. **队里有歌时普通聊天回复会被推迟**：报幕/回执/普通回复和清唱共用 `state.ttsQueue`，
   点了一串歌时 AI 回复可能等到前面歌播完才说（设计如此，避免抢喇叭）。
6. **去重是「本场」**：`state.song.seen` 在进程内存里，服务重启即清空；同一首歌本场只能点一次（`songs.dedupe`）。
7. **AI 兜底词第一句会把完整歌名写进去**（如「今天想唱一首《……》」），歌名特别长时会超过 24 字的建议长度，
   `sing_tts.py` 只警告不报错，合成略慢。
8. **直接调 API 时「关闭/去重/空歌名」只有 JSON error，没有语音提示**；弹幕命令路径会补一句语音（见 §3）。
9. **测试模式 `WT_NO_AUDIO=1`** 下「播放中跳过」不会立即 end（假播放不响应 kill），会等到时间轴走完；
   这是测试模式限制，不是线上行为。
10. **「机械/没情绪」的两个来源（2026-11-08 实测）**：
    - 一是 TTS 侧：`tts.prompt_text` 写成占位符（本机历史配置曾误写「这个声音说的那句话」）时，同一句 25 字只出
      1.0~1.9s、f0 标准差 1.1~1.5 半音（又短又平）；改成正确的「梁山在上，今天大白饭也要变得美味呀。」后
      5.2~7.3s、2.7~4.4 半音。**这也会影响普通聊天回复**（同一套 TTS）。
    - 二是清唱后处理：旧版 melody 是「硬量化 + 强颤音（±20 音分）+ 整句 f0 全替换」，WORLD 重合成有电子味。
      现在默认走 `--natural`（音级音高走旋律、只把音符内 45% 自然起伏混进来、颤音 0.3、不硬量化、句尾轻拖）。
      仍嫌机械就把 `sing.mode` 改成 `read`（纯念唱，零 WORLD 伪影，最稳）。
11. **参考音本身限制情绪上限**：`ref_小奶音_7s.wav` 是视频里的 6.94s 片段（原视频 0.192~7.132s ×0.466），
    4.78~7.13s 其实是下一句开头约 2.35s，而 `prompt_text` 只对应第一句 → 存在**残留文本不匹配**。
    实测把参考音裁到 4.2s 或加低切都更平更慢，没有变好，所以保留现状。
    **想真正「有情绪」只能换参考音**：录/找一条 5~10 秒、本身带笑带起伏的干净人声，替换
    `DEEPLIVE_TTS_REF_AUDIO` 并把 `DEEPLIVE_TTS_PROMPT_TEXT` 改成那条音频的逐字文本（音色会有一点变化）。
    另外 `aux_ref_audio_paths` 只会融合音色、不会带来情绪（已实测同 seed 时长逐帧一致）。
12. **"TTS 清唱" ≠ 真唱**：TTS 是念稿模型，v2 只是把元音拉长/连唱/加颤音来逼近唱腔，底子仍是"说话声"。
    想要真正"会唱"的声音，需要**歌声合成模型（SVS）**（如 Apache-2.0 的 SoulX-Singer：零样本、可按 MIDI/歌词合成并克隆音色）。
    代价：模型 ~2.7GB（预处理模型另 ~6.4GB）、依赖较重（torch2.2/nemo/funasr），本机是 AMD ROCm，需要另建环境，
    预计 1~2 小时；而且**音色会与现在的小奶音有差异**（除非你提供一条自己/该音色的 10~30 秒真唱参考音）。
    另：SoulX-Singer 官方在线 Space 的转写接口今天实测可用（能把参考音转成带音素的 metadata），
    但合成接口返回空音频，暂不可靠。

## 14. 真唱引擎三：RVC 翻唱（2026-11-11 新增）

> 前置：跑 `sing.engine: "rvc"`。它不再用 TTS 逐句"念唱"，而是把**原曲**做一遍翻唱：
> 找原曲 → 下载 → demucs 拆人声/伴奏 → RVC 换成主播声线 → 混音 → 当清唱播放。
> 流水线脚本来自 DSH 插件 `dsh-song-studio`（唱歌工坊，MIT），已复制进 `extras/python/song-cover/`。

### 14.1 和另外两个引擎的区别

| 引擎 | 原理 | 像不像唱歌 | 耗时（4 分钟歌） |
|---|---|---|---|
| `tts`（默认） | GPT-SoVITS 逐句合成 + 旋律拉伸 | 念唱感 | 20~40 秒 |
| `ace` | ACE-Step 生成 a cappella → Seed-VC 换声 | 真唱，但歌词是"唱几句" | 1~3 分钟 |
| `rvc` | 原曲分离 + RVC 换声，保留原曲演唱细节 | **最像真唱**（原曲唱功 + 主播音色） | GPU 1~2 分钟 / CPU 5~15 分钟 |

### 14.2 依赖

1. RVC 声线模型（`.pth` + 可选 `.index`），写一个 `voices.json`：

   ```json
   { "我的声线": { "pth": "D:/models/rvc/my_voice.pth", "index": "D:/models/rvc/my_voice.index" } }
   ```

2. 运行环境二选一：
   - **WSL + ROCm（推荐，GPU）**：Ubuntu 22.04 + PyTorch ROCm + demucs + rvc-python；
     python 在 `/opt/rvc/bin/python`，fairseq shim 在 `/opt/rvc/compat`。
   - **Windows python（CPU 兜底）**：装好 torch/demucs/rvc-python 的 python.exe。

3. RVC 基础模型：`hubert_base.pt`、`rmvpe.pt` 放到 `rvc_python/base_model/`（WSL 里同路径）。

### 14.3 配置项（`config.json → sing.rvc`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `wsl` | `wsl`=WSL 里的 python（GPU）| `local`=Windows python |
| `distro` / `user` | `Ubuntu-22.04` / `root` | WSL 发行版/用户 |
| `python_wsl` | `/opt/rvc/bin/python` | WSL 里的 python |
| `compat_wsl` | `/opt/rvc/compat` | WSL 里的 fairseq shim（免装 fairseq） |

| `voice` | 空 | 用哪个声线（voices.json 的键） |
| `f0` | 0 | 升降调（半音），男女互转常用 ±12 |
| `device` | `cuda:0` | GPU 用 `cuda:0`，CPU 兜底 `cpu:0` |

### 14.8 出一首翻唱（一条命令）

不想开直播、只想先做首歌时，用这个脚本（内部就是 cover.py 的封装）：

```powershell
# 第一次：把模型和一首歌丢进去
.\scripts\rvc-cover.ps1 -Model "D:\models\my_voice.pth" -InputFile "D:\music\宁夏.mp3" -VoiceName 小深

# 有 index / 需要升降调
.\scripts\rvc-cover.ps1 -Model "D:\models\my_voice.pth" -Index "D:\models\my_voice.index" `
  -InputFile "D:\music\宁夏.mp3" -VoiceName 小深 -F0 12
```

参数：

| 参数 | 说明 |
|---|---|
| `-Model` | 必填，RVC `.pth` |
| `-Index` | 可选，`.index` |
| `-InputFile` | 必填，原曲音频（mp3/wav/m4a…） |
| `-VoiceName` | 声线名（写进 voices.json，默认「我的声线」） |
| `-F0` | 升降调半音（男↔女常用 ±12） |
| `-Device` | `cpu:0`（默认）或 `cuda:0` |
| `-OutDir` / `-WorkDir` / `-VoicesFile` | 输出/中间文件/声线表路径（默认放 `-OutDir` 下） |

脚本会自动：写 `voices.json` → 生成 cover 配置 → 跑 demucs 分离 → RVC 换声 → 混音 → 输出 `*_full.mp3`。
实测（假声线模型）：20 秒音频 39 秒出 mp3；4 分钟整首约 6~8 分钟。

鲸live 直播里则不用脚本：`config.json` 设 `sing.engine="rvc"`，弹幕「唱歌 歌名」会自动走同一条流水线。
