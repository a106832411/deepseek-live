# 本地模型（省钱模式）· 本机实操版

目标：把 AI 决策从「按 token 付费的云端接口」换成「本机 Ollama」，token 成本归零，只花电费。

## 1. 本机现状（已跑通）

| 项 | 值 |
|---|---|
| Ollama | `C:\Users\49820\AppData\Local\AMD\AI_Bundle\Ollama\ollama.exe`（0.32.15） |
| 模型目录 | `D:\ollama-models2`（设置环境变量 `OLLAMA_MODELS`） |
| 模型名 | `qwen25-7b-local`（Qwen2.5-7B-Instruct **Q3_K_M**，3.8GB） |
| 速度 | **约 85 tokens/s（GPU）** |
| API | `http://127.0.0.1:11434/v1`（OpenAI 兼容） |

切换后的 `.env`：

```ini
DEEPLIVE_AI_BASE=http://127.0.0.1:11434/v1
DEEPLIVE_AI_MODEL=qwen25-7b-local
DEEPLIVE_AI_KEY=ollama
```

## 2. 模型从哪来（国内网络实测）

- ❌ `registry.ollama.ai` 能连上，但 blob 下载会卡死（不可靠）
- ❌ `huggingface.co` 被墙
- ✅ **ModelScope（魔搭）** 稳定且快：`https://modelscope.cn/models/Qwen/Qwen2.5-7B-Instruct-GGUF`

注意：ModelScope 上 `q4_k_m` 是**分片文件**（`-00001-of-00002.gguf` + `-00002-of-00002.gguf`），Ollama 直接导入分片会报
`split GGUF ... has 1 shards, expected 2`，所以本机用了**单文件的 q3_k_m**（3.6GB）：

```powershell
$env:OLLAMA_MODELS="D:\ollama-models2"
curl.exe -L -C - -o qwen2.5-7b-instruct-q3_k_m.gguf `
  "https://modelscope.cn/models/Qwen/Qwen2.5-7B-Instruct-GGUF/resolve/master/qwen2.5-7b-instruct-q3_k_m.gguf"
```

> 想要 q4_k_m 质量：需要先用 llama.cpp 的 `gguf-split --merge` 合并分片，或找单文件 q4 的仓库。

## 3. 导入 Ollama

在 GGUF 同目录写 `Modelfile`：

```
FROM ./qwen2.5-7b-instruct-q3_k_m.gguf
PARAMETER num_ctx 8192
PARAMETER temperature 0.7
PARAMETER top_p 0.9
```

```powershell
$env:OLLAMA_MODELS="D:\ollama-models2"
ollama create qwen25-7b-local -f .\Modelfile
ollama list
```

导入成功后原始 `.gguf` 可以删掉（Ollama 已复制进 blob 库），省 3.6GB。

## 4. 验证

```powershell
$env:OLLAMA_MODELS="D:\ollama-models2"
ollama serve    # 监听 11434

curl.exe http://127.0.0.1:11434/v1/chat/completions -d '{\"model\":\"qwen25-7b-local\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}],\"max_tokens\":40}'
```

## 5. 接入鲸live

改 `.env` 的 3 个 AI 变量（见上），重启鲸live。实测弹幕「你觉得草莓和蓝莓哪个赚钱」→ 本地模型回复「草莓可能更火些，蓝莓太低调了。」

> 语音还需要本机 GPT-SoVITS 服务（默认 9881）；没启动时只会有文字回复，日志里报 `TTS 异常: connect ECONNREFUSED 127.0.0.1:9881`，属正常。
